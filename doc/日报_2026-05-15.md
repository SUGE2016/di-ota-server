## 二、架构方案进展

### 1. 最终架构决策

已明确最终方案：

- 设备直接调用 `ota-server`：
  - `POST /device/v1/check-update`
  - `POST /device/v1/report-status`
- 设备继续直接调用主系统上报业务状态和当前固件版本。
- 主系统不调用 `ota-server`。
- `ota-server` 不调用主系统。
- 主系统不关心 OTA 任务、包、升级记录、失败原因和回滚状态。
- OTA 发布范围通过 CSV 设备清单导入 `ota-server`。

### 2. CSV 契约

确定 CSV 字段：

```csv
device_id,product_code,product_model,hardware_version,current_version,device_group,tags
AMS000001,AMS,V9,1.0,v2.3,org-1001,"{""batch"":""2026-05""}"
```

字段原则：

- `device_id`、`product_code`、`product_model`、`hardware_version` 必填。
- `current_version` 可空。
- `device_group` 可空，导入时默认为 `default`。
- `tags` 可空，非空时必须是 JSON object。
- 不导出姓名、手机号、地址、紧急联系人、业务事件等敏感数据。

## 三、ota-server 实现进展

分支：`feat/ota-csv-device-catalog`

### 1. 设备 API 鉴权与状态上报增强

已完成：

- 增加 `DEVICE_API_AUTH_ENABLED`。
- 增加 `DEVICE_API_TOKEN`。
- `/device/v1/check-update` 与 `/device/v1/report-status` 支持可选 Bearer token 鉴权。
- `report-status` 要求 `task_id`。
- `report-status` 支持并持久化：
  - `source_version`
  - `target_version`
  - `error_code`
- 保持幂等处理逻辑。

### 2. CSV 设备目录导入

新增能力：

- `GET /api/v1/devices`
- `GET /api/v1/devices/csv-template`
- `POST /api/v1/devices/import-csv`

导入逻辑：

- 校验 CSV 表头。
- 校验必填字段。
- 校验字段长度。
- 校验重复 `device_id`。
- 校验 `tags` 必须是 JSON object。
- 将数据 upsert 到 `t_device` 设备影子表。
- 重复导入会更新分组、型号、硬件版本、当前版本、产品代码和 tags。

### 3. 管理台设备页接入

更新 `frontend/src/pages/DevicesPage.tsx`：

- 从真实 `/api/v1/devices` 加载设备影子表。

- 支持 CSV 上传导入。
- 支持按设备分组过滤。
- 支持关键字搜索设备 ID、产品代码、型号、硬件版本、当前版本、分组。
- 移除原 mock 数据口径。

### 4. 发布任务创建体验

### 2. 新增 OTA CSV 导出

新增接口：

```http
GET /api/devices/ota-csv
Authorization: Bearer <token>
```

导出字段与 `ota-server` CSV 模板对齐：

- `device_id`
- `product_code`
- `product_model`
- `hardware_version`
- `current_version`
- `device_group`
- `tags`

权限范围沿用设备列表逻辑：

- 普通用户只能导出自己绑定设备。
- 平台管理员导出所属平台设备。
- 机构用户导出本机构设备。
- 超级管理员可导出全部设备。
