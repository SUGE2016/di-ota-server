## 二、架构方案进展

### 1. v2 核心决策

- **C 直连 O**：`check-update`、下载、 `report-status` 仍由设备直连 `ota-server`。
- **B↔O 受控集成**：B 推送目录 `catalog/sync`；B 拉取 `pending-upgrades` 作 hint，不代理大包、不裁决升级。
- **O 域闭环**：注册表校验、任务快照、版本策略、可解释拒绝码、Success 回写 `reported_version`。
- **可降级**：集成 API 不可用时，CSV 导入 + C 直 poll O 仍可用。

### 2. 文档产出

- `doc/架构改进方案_v2_2026-06-05.md`（含 catalog sync 版本倒退 / 身份冲突策略 §5.5）。
- `README.md` 补充 v2 已实现能力与本地联调步骤。

## 三、ota-server 实现进展

分支：`feat/ota-csv-device-catalog`

### 1. 数据库迁移（P0）

- `backend/migrations/005_architecture_v2.sql`：
  - 设备表双版本字段（`current_version` / `reported_version`）。
  - `t_task_target` 任务目标快照。
  - `t_catalog_sync_batch` 目录同步批次审计。

### 2. check-update / report-status（P0）

- 新模块：`check_update_handler.go`、`version_compare.go`、`registry_queries.go`、`package_queries.go`。
- 注册表存在性 / 产品型号 / 硬件版本校验。
- 任务 Running 时按快照匹配；拒绝码可解释（未注册、无任务、版本不符等）。
- `report-status` Success 回写 `reported_version`。
- 任务创建 / start 时生成 `t_task_target` 快照；CSV 导入复用 `applyCatalogDevice` 冲突策略。

### 3. B↔O 集成 API（P1 / P2）

- `integration_handlers.go`：
  - `POST /api/v1/integrations/catalog/sync`（`INTEGRATION_ENABLED` + `INTEGRATION_SERVICE_TOKEN`）。
  - `GET /api/v1/integrations/pending-upgrades`。
- `.env.example` / `config.go` 增加 `INTEGRATION_*` 配置。

### 4. 测试体系（TDD）

- `tests/specs/`：check-update v2、integration catalog/hint、device CSV、升级状态机等行为规格。
- `tests/fixtures/`：有效 / 无效 CSV 夹具。
- `backend/internal/server/*_test.go`：单元测试（catalog sync、版本比较、canary 等）。
- `backend/tests/integration/`：HTTP + sqlmock 集成测试。
- `tests/README.md` 说明目录结构与运行方式。

### 5. 设备模拟器

- CLI：`cmd/device-simulator/main.go`（check-update → 模拟下载 → report-status 全流程）。
- Web：`frontend/src/pages/DeviceSimulatorPage.tsx`，路由 `/#/simulator`；逻辑在 `frontend/src/lib/deviceSimulator.ts`。
- 登录页底部增加「设备端模拟器」链接。
