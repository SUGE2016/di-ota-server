## 三、后端

### 1. 设备鉴权

- 迁移 `007_device_secret.sql`：`t_device.device_secret`。
- `device_auth.go`：`Authorization: Device device_id=...,timestamp=...,signature=...`，HMAC-SHA256 覆盖 `timestamp + method + path + sha256(body)`。
- `DEVICE_API_AUTH_ENABLED=true` 时启用；联调可 `false` 跳过。
- `PUT /api/v1/devices/:device_id/device-secret`：运维/产线写入 secret。

### 2. 设备 API（仅 `/device/v1/`）

- **check-update**：仅 `device_id`、`current_version`；不再要求 `group/product_model/hardware_version`，不再返回 `identity_mismatch`。
- **report-status**：逻辑提取至 `report_status_handler.go`；与 check-update 共用同一套 HMAC 校验（读 body 后验签）。

### 3. 配置

- `.env.example`：`DEVICE_AUTH_TIMESTAMP_TOLERANCE_SEC`；移除 `DEVICE_API_TOKEN` / `DEVICE_API_AUTH_MODE`。
- `cmd/api/main.go` 自动迁移列表增加 `007_device_secret.sql`。

## 五、设计取舍（评审结论）

- **不做** v1/v2 双轨与全型号共享 Bearer Token。
- **不做** group 等字段 hash 传输；HTTPS + 服务端查库即可。
- **保留** `current_version`：平台记录滞后时只读补充，Success 仍以 report-status 回写为准。
